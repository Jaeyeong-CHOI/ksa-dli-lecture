# 단계별 복사 프롬프트

웹 단계 번호와 같습니다. 기존 Skill은 Installed 목록의 Try in chat으로 호출합니다. 새 Skill은 Create with chat에서 시작합니다. 입력창에 선택한 Skill 이름이 보이는지 확인하고 아래 요청만 추가합니다. {{TEAM}}과 {{PROJECT}}는 실제 조회한 대상 값으로 바꿉니다.

## 2. 실행할 작업 공간 준비하기

실행 위치: ChatGPT 웹 → Work · 별도 실습 프로젝트



### 보낼 요청문

~~~text
이 공개 데이터 실습 프로젝트에서 사용할 수 있는 Skill·파일 생성과 다운로드·브라우저 확인 기능, Node.js/npx와 Python 3 실행 여부를 확인해 주세요. 개인 메모리·메일·Drive·다른 프로젝트는 사용하지 마세요. 아직 프로그램 설치나 계정 연결은 하지 말고 실제 확인한 항목과 없는 항목을 구분해 주세요.
~~~

## 3. 이미 만들어진 Skill 하나 설치하기

실행 위치: ChatGPT 웹 Work · k-skill 검토 → 등록 → Try in chat

준비한 Work 대화에 요청합니다. 결과 ZIP은 내 컴퓨터로 다운로드 → Skills → Create → Upload from your computer → 그 ZIP 선택 순서로 등록합니다. 이미 Skill 카드의 Install로 등록했다면 업로드를 반복하지 않습니다.

### 보낼 요청문

~~~text
공개 저장소 https://github.com/NomaDamas/k-skill 의 geeknews-search 폴더만 사용하겠습니다. 먼저 SKILL.md와 instruction.md, 실행 코드와 의존성을 읽어 설명해 주세요. 원본 절차를 바꾸지 않고 이 웹 계정의 Skills에 등록 가능한 Skill 카드 또는 standalone Skill ZIP으로 준비하세요. ZIP에는 원본 SKILL.md와 필요한 보조 파일을 포함하세요. 기존 동명 Skill은 덮어쓰지 말고 다른 Skill·설정은 변경하지 마세요. 파일 생성과 계정 등록 상태를 구분하고 원본 작성자와 출처를 남겨 주세요. 공개 데이터만 사용하세요.
~~~

## 4. 뉴스를 읽고 원문과 대조하기

실행 위치: ChatGPT 웹 Work · 등록한 geeknews-search의 Try in chat

Installed 목록 → geeknews-search → Try in chat을 누릅니다. 입력창에 선택된 Skill 이름이 보이면 아래 요청만 추가합니다. @geeknews-search라는 글자를 쓰는 것만으로 선택이 완료된 것은 아닙니다.

### 보낼 요청문

~~~text
현재 피드의 최신 글 5개를 조회하고 제목·게시 시각·링크를 보여 주세요. 각 글의 피드 요약을 한 문장으로 정리하고, 읽을 만한 글 2개와 그 이유를 골라 주세요. 피드 요약만 읽은 부분과 원문까지 확인한 부분을 구분하고, 실제 호출과 결과를 보여 주세요.
다음 요청에서는 방금 반환된 제목의 키워드 하나로 피드 안에서 검색하겠습니다.
~~~

## 7. 공공데이터를 가져오는 새 Skill 만들기

실행 위치: ChatGPT 웹 Skills → Create → Create with chat

Skills → Create → Create with chat으로 열린 입력창에서 Skill Creator가 선택되어 있는지 확인하고 아래 요구사항을 덧붙입니다. 기존 Skill을 실행하는 Try in chat과는 다른 단계입니다.

### 보낼 요청문

~~~text
국가유산청 공공데이터 API를 호출하는 새 Skill heritage-brief를 만들어 주세요. 기존 k-skill의 문화유산 Skill을 설치하는 작업이 아닙니다.
공식 설명: https://www.data.go.kr/data/15034324/openapi.do
목록: https://www.khs.go.kr/cha/SearchKindOpenapiList.do
상세: https://www.khs.go.kr/cha/SearchKindOpenapiDt.do

입력은 국가유산명 검색어와 결과 수(기본 3, 최대 5)입니다. 목록의 ccbaKdcd·ccbaAsno·ccbaCtcd를 문자열 그대로 상세 조회에 사용하세요. Python 표준 라이브러리로 XML을 읽고 이름·유형·지역·주소·설명·공식 출처·조회 시각을 JSON으로 저장하세요.
SKILL.md에는 적용 상황·수행 절차·완료 기준, scripts에는 재사용 호출 코드, references에는 확인한 API 계약을 분리해 주세요.
정상 결과·검색 결과 없음·통신/XML 오류를 구분하고, 운영시간·입장료는 추측하지 마세요. 경복궁과 첨성대 두 입력으로 검증하고 실행한 검사와 미실행 검사를 나눠 보고하세요. 배포는 포함하지 마세요. 실제 생성 위치와 호출 방법도 알려 주세요.
이 웹 계정의 Skills 목록에서 재사용할 수 있도록 저장·등록하고 실제 상태를 확인하세요. 같은 이름이 있으면 덮어쓰지 마세요. Skill Creator 적용·파일 생성·등록·실제 API 호출·모의 검사를 따로 보고하세요. 공개 데이터만 사용하며 개인 메모리·메일·Drive·다른 프로젝트는 제외합니다.
~~~

## 8. 경복궁 결과를 최대 3개 요청하기

실행 위치: 등록한 heritage-brief → Try in chat

heritage-brief → Try in chat으로 새 대화를 엽니다. 아래 요청문에 경복궁·최대 3개가 이미 들어 있어 입력 A 파일을 별도로 첨부하지 않아도 됩니다.

### 보낼 요청문

~~~text
검색어는 경복궁, 최대 결과는 3개입니다. 선택된 heritage-brief로 실제 API를 호출해 heritage-a.json을 만들고 다운로드로 제공해 주세요. 전체 일치 수·수집 수·상세 성공 수와 오류 여부를 구분하고 사람이 읽을 표도 함께 보여 주세요. 항목 하나의 공식 원문과 이름·주소를 대조하고 출처·조회 시각을 남기세요. 파일이 이미 있으면 새 이름을 사용하고 배포하지 마세요.
~~~

## 9. 입력을 바꾸고 실패도 확인하기

실행 위치: ChatGPT Work · 새 작업 + 같은 @heritage-brief

같은 Skill의 Try in chat으로 새 입력을 줍니다. 요청문에 첨성대와 오류 확인용 검색어가 모두 들어 있습니다. 앞 단계에서 받은 A 파일은 내 컴퓨터에 보관합니다.

### 보낼 요청문

~~~text
검색어는 첨성대, 최대 결과는 3개입니다. 선택된 heritage-brief로 새 API 호출을 수행해 heritage-b.json을 만들고 다운로드로 제공하세요. A 파일을 덮어쓰거나 A의 내용을 재사용하지 마세요. 이어서 존재하지않는유산zzzz를 조회해 반환 상태를 확인하세요. 정상 응답이 0건일 때만 no_results로 보고하고 통신 실패를 0건으로 바꾸지 마세요. 없는 결과를 채우지 말고, 통신이 실패하면 오류를 남기고 반복 호출을 멈추세요.
~~~

## 10. 통신이 막혔다면 XML로 이어가기

실행 위치: 기존 Skill Creator 대화에서 수정 → 저장 → 등록된 Skill의 새 대화에서 실행

처음에는 아래 “실제 XML 첨부 예제” ZIP을 사용하세요. 직접 주소를 조합하거나 XML을 저장하지 않아도 됩니다. ZIP 첨부가 지원되지 않으면 압축을 풀어 안의 XML 두 파일과 README를 첨부합니다.

### 1. Skill 수정 요청

~~~text
이 대화에서 만든 heritage-brief에 명시적으로 첨부한 XML을 처리하는 경로를 추가해 주세요. 첨부한 ZIP의 README와 XML부터 읽으세요. 기본은 실제 API 호출이고, 첨부를 처리할 때만 sourceMode=provided_snapshot과 원래 수집 시각을 기록하세요. 누락된 상세의 주소·설명은 null(모름)로 두고 partial(일부 결과)로 구분하세요. 전체·수집·상세 성공·누락 수와 앞자리 0이 실제 첨부에서 보존되는지 검사하세요. 현재 Skill을 업데이트·저장하고 변경 내용과 검사 결과를 설명하세요. 새 대화에서 같은 첨부로 실행할 방법을 알려 주세요. 아직 페이지 제작이나 배포는 하지 마세요.
~~~

### 2. 저장된 Skill 실행 요청

수정한 heritage-brief → Try in chat · 같은 ZIP을 다시 첨부한 뒤

~~~text
선택된 heritage-brief로 이 대화에 첨부한 ZIP의 실제 XML을 처리해 heritage-snapshot.json을 만들고 다운로드로 제공해 주세요. 실시간 API를 다시 호출하지 마세요. 원래 수집 시각·sourceMode·처리 상태·전체·수집·상세 성공·누락 수를 사람이 읽을 표로도 보여 주세요. 누락된 주소·설명을 만들지 말고 등록된 Skill의 실제 실행 기록을 보여 주세요.
~~~

## 11. 검증한 데이터를 작은 웹페이지로

실행 위치: 검증한 API 결과 또는 명시적 첨부 스냅샷이 있는 Work 작업

새 Work 대화에 본인이 확인한 JSON 파일 하나를 첨부합니다. API 성공이면 heritage-a.json, XML 복구 후라면 heritage-snapshot.json입니다. 파일 이름이 보이면 아래 요청을 보냅니다. 오류 메시지만 든 JSON은 데이터 대신 쓰지 않습니다.

### 보낼 요청문

~~~text
이 대화에 첨부한 검토된 결과 JSON으로 한국어 국가유산 탐색 페이지를 하나의 index.html로 만들어 주세요. JSON을 안전하게 내장하고 원본 값과 출처·시각을 유지하세요. 이름·유형·지역 검색, 표시 건수·0건 안내·초기화, 설명 펼치기와 공식 출처 링크를 제공하세요. 두 입력 결과가 모두 정상일 때만 A/B 전환을 추가하고 실패 결과를 성공 데이터로 만들지 마세요. 전체·수집·상세 성공·현재 표시 수를 구분하세요. 조회해 내장한 데이터는 스냅샷이고 브라우저가 API를 새로 호출하지 않는다고 표시하세요. 상세가 없으면 그 사실을 그대로 표시하세요. label·키보드 focus·모바일을 지원하고 외부 라이브러리·로그인·DB·새 API는 추가하지 마세요. 아직 배포하지 마세요. 완성 HTML을 다운로드로 제공하세요. 파일명만 말하거나 코드 블록으로만 끝내지 마세요.
~~~
